# 상황 가정 시나리오 — Loopers 조회 성능 개선 스토리

---

## 서비스 프로필

**Loopers — 감성 라이프스타일 셀렉트숍**

패션, 리빙, 문구, 소품 등 감성 브랜드를 큐레이션하는 버티컬 커머스.

| 항목 | 수치 | 근거 |
|------|------|------|
| 입점 브랜드 | ~500개 | 무신사 8K, 올리브영 수천 대비 중소 규모 |
| 상품 수 | ~10만 SKU | 브랜드당 평균 200개 |
| 회원 수 | ~50만 명 | DAU 3~5만 기준 역산 |
| DAU (평일) | ~3만 명 | TPS 50 역산 |
| DAU (시즌 세일) | ~6~8만 명 | TPS 100~120 역산 |
| DAU (세일+콜라보 드롭) | ~20만 명 | TPS 400 역산 |
| **설계 목표** | **TPS 1,000까지 버티는 구조 (단일 서버)** | 크리스마스 교훈 + 2.5배 여유분. 단일 서버 + 캐시 + 인덱스로 TPS 2,000~3,000 천장 |

## 트래픽 프로필

### 평일 기본 — TPS 50

| 요청 유형 | 비중 | TPS | 설명 |
|-----------|------|-----|------|
| 상품 목록 조회 | ~40% | ~20 | 메인페이지, 카테고리, 검색 결과 |
| 상품 상세 조회 | ~25% | ~12 | 상품 클릭 후 상세 |
| 인증/회원 | ~15% | ~8 | 로그인 검증, 회원 정보 |
| 좋아요/장바구니 | ~10% | ~5 | 찜하기, 장바구니 담기 |
| 주문/결제 | ~5% | ~2~3 | 주문 생성, 쿠폰 적용 |
| 브랜드/기타 | ~5% | ~2~3 | 브랜드 목록, 쿠폰 목록 |

- DB 커넥션 풀 20~30개로 충분. 문제 없이 운영.

### 시즌 세일 — TPS 100~120

- 크리스마스, 설날 등 시즌 이벤트 기간
- DAU 2배, 상품 목록/상세 조회에 트래픽 집중
- 인기순 정렬 요청 비중 급증

### 세일 + 콜라보 드롭 피크 — TPS 400

| 요청 유형 | TPS | 특징 |
|-----------|-----|------|
| 상품 목록 | ~160 | 세일 페이지 접속 폭증, 인기순 정렬 대부분 |
| 상품 상세 | ~120 | 한정판 등 특정 인기 상품(핫키)에 집중 |
| 좋아요 | ~40 | "좋아요 눌러두고 오픈런 대기" |
| 주문/결제 | ~20 | 드롭 시작 직후 주문 폭증 |
| 인증 | ~40 | 로그인 러시 |
| 브랜드/쿠폰 | ~20 | 쿠폰 발급 몰림 |

### 종합

```
시즌 세일 단독:     평소의 1.5~2.5배 (DAU 기준)
시즌 세일 피크:     평소 피크의 3배 (뮤진사 인프라 설계 기준)
한정판 드롭 단독:   수배~수십 배 (순간 스파이크)
시즌 + 드롭 겹침:   5~10배 (추정)
```

→ **TPS 50 → 400 (8배)은 "시즌 세일 + 브랜드 콜라보 드롭 겹침" 구간에 해당. 현실적 수치.**

## 이벤트 유형

**A + B 조합: 시즌 세일 + 브랜드 콜라보 한정판 드롭**

- 시즌 세일은 며칠간 지속적으로 높은 트래픽 → 인덱스 최적화의 이유
- 콜라보 드롭은 특정 시점에 순간 스파이크 → 캐시의 이유
- 두 가지가 겹치면서 TPS 400 형성

## 스토리 타임라인

### 글의 톤: "미리 준비한다"

작년 크리스마스에 장애를 겪고, 이번 설날에는 구조적으로 대비한다는 흐름.

### 작년 크리스마스 — "홀리데이 감성 셀렉트" 기획전, 그리고 장애

> **기획전 구성**
>
> 12월, Loopers는 "홀리데이 감성 셀렉트" 기획전을 열었다.
>
> - 메인 큐레이션: 올겨울 메가 트렌드 **하프기장 페이크퍼 코트**,
>   팬톤 올해의 색 **모카무스 톤** 머플러, **버건디 니트** 컬렉션
> - 콜라보: 인기 일러스트레이터 "따뜻한 손끝" × 홈웨어 브랜드 "포근공방"
>   → **크리스마스 한정판 커플 파자마 세트** (선물용 패키징 포함)
> - 선물하기 서비스: 향수(졸마론, 디프틱), 캔들 세트, 파자마 기프트 등
>   → "선물하기" 거래액 급증
>
> **장애 발생**
>
> DAU가 평소의 3배 가까이 뛰었고, 피크 시간에 TPS가 250까지 올라갔다.
> 팀에서는 시즌 세일 수준인 TPS 150 정도를 예상하고 있었다.
>
> - 상품 목록 응답이 2~3초까지 느려졌다. 인기순 정렬 요청이 몰리니
>   DB가 매번 Full Scan + filesort를 돌리고 있었다.
> - "따뜻한 손끝 × 포근공방" 한정판 상세 페이지에 트래픽이 쏠리면서
>   피크 시간에 주문 타임아웃이 간헐적으로 터졌다.
>
> 급하게 서버 스케일업/스케일아웃으로 버텼다. 근본 원인은 손대지 못했다.
> "일단 서버 늘리니까 됐으니까" — 하지만 다음에도 이렇게 넘길 수 있을까.

### 이번 설날 — "설렌타인 감성 마켓" + 브랜드 콜라보 드롭 예정

> **상황: 설날(2/17)과 발렌타인(2/14)이 같은 주에 겹치는 "설렌타인" 특수.**
>
> 마케팅팀에서 연락이 왔다.
>
> "이번 설날은 발렌타인이랑 겹쳐서 '설렌타인 감성 마켓'으로 기획전을 연다.
> 거기에 디자이너 브랜드 '마르꽁'이랑 Loopers 단독 SS26 리미티드 에디션
> 콜라보 드롭도 같이 진행한다. SNS 사전 등록이 역대급이다."
>
> **기획전 구성**
>
> - 설 선물 큐레이션: 프리미엄 차 세트(오솔록), 감성 디퓨저, 홈웨어
> - 발렌타인 큐레이션: 커플 아이템, 향수, 감성 리빙 소품(캔들, 배쓰 세트)
> - SS26 프리뷰: 올봄 트렌드 **레드 컬러** 아이템, **슬립드레스**, 데님
> - **콜라보 드롭**: "마르꽁 × Loopers" 단독 리미티드 에디션
>   → SS26 시즌 워시드 데님 텍스처 + 자수 디테일 한정 아이템
>   → 설렌타인 한정이라는 타이밍에 희소성까지 겹침
>
> **트래픽 예상**
>
> 크리스마스 때 150으로 예상했다가 250이 터졌다.
> 이번 설날은 크리스마스급 세일에 발렌타인 겹침, 거기에 콜라보 드롭까지.
> 최소 300, 순간 400 이상도 가능하다.
>
> 크리스마스 때 예상의 1.67배가 터진 교훈이 있다.
> 이번엔 예측이 또 빗나가도 괜찮도록,
> **목표 400, 피크 1,000까지 버티는 구조로 준비한다.**
> 단일 서버 + 캐시 + 인덱스로 TPS 2,000~3,000까지 천장이 있으니,
> 1,000은 충분히 안전 범위다.
>
> 작년처럼 서버만 늘려서 넘길 수 없다.
> 이번엔 구조적으로 준비하기로 했다.

### 문제 해결 과정 — 테크니컬 라이팅 본문

```
[D-28 — 현황 분석]
  EXPLAIN 돌려보니 상품 목록: Full Scan + filesort.
  주문 목록: member_id 인덱스 부재.
  TPS 50에서도 이미 비효율적이었는데, 숫자가 적어 안 드러났을 뿐.
  작년 크리스마스에 서버를 늘려도 느렸던 이유가 여기 있었다.
  → "서버를 늘리기 전에, 쿼리부터 잡자."

[D-21 — 인덱스 적용]
  단일 인덱스 3개: (likes_count DESC), (created_at DESC), (price)
  복합 인덱스 1개: (brand_id, likes_count DESC) — 브랜드 필터 + 인기순 filesort 제거
  주문/쿠폰 인덱스: (member_id, created_at DESC), (member_id), (coupon_id)
  EXPLAIN 검증 → Full Scan + filesort 전부 제거. 쿼리 96.9% 개선 (23ms → 0.7ms).
  → "DB 조회 자체는 버틸 수 있게 됐다.
     하지만 TPS 1,000이면 같은 데이터를 초당 수백 번 DB에서 읽는다.
     서버를 늘려도 DB는 하나 — DB가 병목이 된다."

[D-14 — 캐시 적용]
  상품 목록: Redis (TTL 3분, page 1~3만 캐싱, @Scheduled 2분 주기 워밍)
  상품 상세: Redis (TTL 5분, CUD 시 @CachePut 덮어쓰기)
  브랜드 목록: Caffeine 로컬 캐시 (TTL 10분)
  쿠폰 상세: Redis (TTL 10분, CUD 시 @CacheEvict)
  → "DB 접근 자체를 줄이자. 캐시 효과 = f(캐시 미스 비용) × f(트래픽 규모).
     인덱스가 기본(-76%), 캐시가 증폭기(+25%), 둘 다 적용 시 -82%."

[D-7 — 캐시 정합성 전략]
  Ghost Stock 취약점 발견: 주문으로 재고 차감 → 캐시는 TTL까지 옛날 재고 노출.
  → 재고 분리 전략: 상품 정보(캐시) + 재고(DB PK 실시간 조회). 정확도 91%.
  좋아요: 캐시 없음, 원자 SQL (likes_count + delta) 단일 TX.
  주문: 캐시 없음, 재고 차감 + 쿠폰 사용 + 주문 생성 단일 TX.
  목록 CUD: @CacheEvict(allEntries=true) — 관리자 저빈도 전제.
  상세 CUD: @CachePut — 삭제가 아닌 덮어쓰기로 캐시 미스 방지.
  → "고수는 삭제하지 않고 덮어쓴다."

[D-Day — 설날 세일 + 콜라보 드롭]
  TPS 400 피크. 목표 1,000까지 버티는 구조 — 2.5배 여유분.
  캐시 히트율 90%+. 워밍 스케줄러가 TTL 만료 전 재적재.
  마르꽁 드롭: 재고 분리 덕에 Ghost Stock 없이 정확한 재고 노출.
  → 무사히 통과.

[D+7 — 회고]
  모니터링 수치 정리. 다음 단계 도출.
  현재 단일 서버 천장 TPS 2,000~3,000.
  그 너머: 서버 2대 + LB (3,000+), Read Replica (5,000+),
          Redis Cluster + DB 샤딩 (10,000+), CQRS + 이벤트 소싱 (50,000+).
```

> 설렌타인 한정이라는 타이밍 + 희소성 + SS26 신상 프리뷰가 겹침.
>
> - 종류: 리미티드 데님 재킷 (2컬러), 자수 크로스백 (1종)

- 러쉬방 발렌타인 한정판 → 설렌타인 겹침으로 수요 폭증
- 오솔록 차 세트 → 설 선물 수요 집중

- 작년 크리스마스에 스케일업/아웃으로 버텼지만, 그건 해결이 아니라 회피였다

- 이번 설날에는 "서버를 늘리기 전에, 쿼리부터 잡자" → "DB 접근 자체를 줄이자" 순서로 구조적 대비
